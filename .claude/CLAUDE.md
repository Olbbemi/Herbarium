# 커밋 규칙

이 프로젝트에서 파일이 생성·수정되는 모든 경우에 아래 규칙을 따른다.

사용자가 명시적으로 커밋을 요청하기 전까지 커밋하지 않는다.
파일을 쓰거나 편집한 직후 자동으로 커밋하지 않는다.

# knowledge-promote 워크플로

1. `promote/<id>` 브랜치를 새로 만든다.
2. 확정지식 파일을 해당 브랜치에 쓴다.
3. 파일 경로를 사용자에게 알리고 검토를 요청한다. 파일 내용을 대화창에 통째로 출력하지 않는다.
4. 사용자가 승인하면 커밋 후 push 한다.
5. `gh pr list --head promote/<id>` 로 해당 브랜치의 PR 존재 여부를 확인한다.
   - PR 이 없으면 `gh pr create` 로 새 PR 을 생성한다.
   - PR 이 이미 있으면 PR 을 새로 만들지 않는다 (커밋·푸시로 기존 PR 에 반영된 것으로 간주).
6. 이후 머지는 사용자가 직접 한다.
